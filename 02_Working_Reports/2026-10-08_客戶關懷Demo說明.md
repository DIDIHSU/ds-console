# 客戶關懷 UI Demo（2026-10-08）

入口：側欄「客戶關懷」，或營運總覽 → 客戶總覽 → 客戶關注與 AI 關懷。

## 建議展示順序

1. 提醒規則：调整門檻、啟用／停用、保存，執行規則檢查看符合訊號數量。檢查使用固定範例，不新增重複案件。
2. 關懷工作台：晨港物流展示低使用情境；遠星科技展示使用下降；星河教育展示功能推薦；綠沐生活展示已有客服案件而暫緩。
3. 選擇公司 → 開始 AI 判讀 → 查看事實、可能解讀與建議 → 選擇聯繫目的 → 產生 Mail 草稿。
4. 修改收件人、主旨或正文；編輯後審核勾選失效。勾選確認才可模擬寄送。
5. 可先切換模擬失敗，再切換成功重試。成功後案件鎖定寄送，避免重複發送。
6. 關懷紀錄查看已確認信件快照、審核人與下次聯繫日；通知中心也新增展示紀錄。
7. 暫緩 7 天、解除提醒、重新開啟案件皆可展示。重置展示或重新整理回復預設情境。

## 實作界線

資料、AI 解讀與 Mail 皆為固定情境產生，無後端、無 AI API、無真實寄送；只保存於本次頁面記憶體。
規則檢查重算固定 E2B 訊號數量；官網缺少完整歷史資料，顯示尚未提供。未實作排程服務與真實退訂檢查。
原有到期、停用、名額提醒保留；公司與產品管理仍在原頁面。

## 2026-10-08 規則設計更新

提醒規則已改為文字規範流程，取代上述數字門檻／單位與重算方式：
1. 新增文字規則，填寫名稱、適用產品與需求描述。
2. AI 解析並整理規範（Demo 將原文整理為草稿，不是真實語意解析）。
3. 修改規範並勾選確認；修改描述需重新解析，修改規範需重新確認與試跑。
4. 試跑：原始內建範例提供固定逐公司結果；自訂或修改的規範顯示待 AI 判斷，不套用舊門檻。
5. 保存並啟用版本；後续可停用或編輯，正式版本在確認新版本前保留。
6. 執行規則檢查只展示載入啟用規範，不進行真實分類。

後端目標：AI 讀取已確認規範與公司資料，回傳符合／不符合／資料不足，以及證據、理由與建議；程式管理資料、版本、流程與審核，不逐條寫業務判斷邏輯。
關懷信仍需人員確認。後續可聯繫日期改為依規範由 AI 建議、待人員確認。
新增規則、確認與試跑門檻、版本保存、範例／自訂結果隔離、關懷信流程及 npm run build / check 通過。

## 規則清單與詳情互動更新

提醒規則預設顯示清單：規則名稱／版本、產品、AI 判斷描述、啟用狀態、查看詳情。

只有按新增規則才開啟空白新增表單。保存後關閉彈窗並更新清單。支援關閉按鈕、Escape、Tab 焦點循環。
