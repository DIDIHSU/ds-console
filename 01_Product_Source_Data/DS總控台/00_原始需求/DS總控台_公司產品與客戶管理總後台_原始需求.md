請幫我建立一套「公司產品與客戶管理總後台」的高擬真前端 Demo，作為公司內部討論、需求確認與操作流程展示使用。

請先閱讀完整需求、檢查目前專案結構，再開始開發。

# 一、系統定位

這套系統是公司內部使用的營運總後台，主要負責統一管理：

1. 公司目前提供的產品
2. 各產品包含的功能
3. 產品與功能的啟用、維護、測試及下架狀態
4. 產品版本與功能發布
5. 官網 HTML 版型的上傳、定義、測試及發布
6. 客戶公司購買的產品
7. 客戶的使用期限、狀態及權限
8. 客戶使用的官網版型
9. 使用額度、到期提醒及操作紀錄

這不是單純的 CRM，也不是一般電商後台，而是公司內部控管「產品、功能、版型與客戶使用權限」的總控台。

# 二、目前產品架構

公司目前有兩個獨立產品：

1. E2B
2. 官網方案

請勿將「官網方案」理解成 E2B 底下的收費等級。

E2B 與官網方案是兩個不同產品，但都由同一套總後台管理。

客戶可能：

* 僅購買 E2B
* 僅購買官網方案
* 同時購買 E2B 與官網方案

目前不要自行加入：

* 基本版
* 進階版
* 企業版
* AI 官網建置
* AI 商品內容生成
* 營運分析平台

除非未來明確新增，否則目前產品固定只有「E2B」與「官網方案」。

# 三、Demo 開發原則

這一版的目標是公司內部討論，請先完成可操作的前端 Demo。

開發要求：

* 使用繁體中文
* 桌面版優先
* 具備基本響應式設計
* 先不要串接真實後端或資料庫
* 使用 Mock Data 呈現完整情境
* 不需要真實登入
* 不需要真實寄送通知
* 不需要真實部署 HTML 版型
* 按鈕、搜尋、篩選、頁籤、彈窗、抽屜與開關都要可以操作
* 新增、編輯、切換狀態後，要更新前端資料
* 不要只製作靜態畫面
* 不要用「功能開發中」替代需求中的主要頁面
* 共用元件需模組化，不要把所有內容寫在單一檔案
* Mock Data 集中管理，保留未來改接 API 的空間
* 如果目前已有專案，沿用現有框架與設計系統，不要破壞既有功能
* 如果目前是空白專案，建立可直接執行的前端專案

# 四、視覺風格

請設計成現代、專業且可實際使用的 SaaS 管理後台。

視覺要求：

* 白色與淺灰色背景
* 深藍色作為主要文字色
* 藍色與青綠色作為主要品牌色
* 綠色表示正常、啟用或已上線
* 橘色表示警告、維護或即將到期
* 紅色表示停權、異常、已到期或下架
* 卡片使用適度圓角及輕微陰影
* 資訊量可以豐富，但層級要清楚
* 不要設計成行銷官網
* 避免過大標題及過度留白
* 狀態不能只靠顏色判斷，必須搭配文字或圖示
* 表格欄位過多時，請妥善設計欄寬與響應方式，避免無意義的水平溢出

# 十一、HTML 版型檢查結果

上傳 HTML 或 ZIP 後，Demo 要模擬顯示：

* 是否存在首頁進入檔案
* HTML 是否能正常解析
* CSS 資源是否完整
* JavaScript 資源是否完整
* 圖片資源是否缺失
* 字型資源是否缺失
* 是否引用外部資源
* 是否包含不安全的 Script
* 是否支援響應式顯示
* 是否產生水平溢出
* 是否有明顯版面錯誤
* 是否符合目前官網系統版本

檢查狀態：

* 檢查通過
* 有警告但可使用
* 檢查失敗
* 等待人工確認

若檢查有問題，必須列出明確原因，不可只顯示「檢查失敗」。

例如：

* 找不到 index.html
* images/banner.jpg 資源不存在
* 使用不允許的外部 Script
* 手機寬度下產生水平溢出
* 版型版本不相容

# 十二、版型版本管理

同一版型可以存在多個版本。

範例：

* v1.0.0：初次上架
* v1.1.0：新增商品列表區塊
* v1.1.1：修正手機版顯示問題

版型詳情頁顯示：

* 目前正式版本
* 目前測試版本
* 歷史版本
* 每個版本的上傳檔案
* 檔案檢查結果
* 更新說明
* 發布範圍
* 發布時間
* 發布人員
* 使用此版本的客戶數
* 預覽版本
* 設為正式版本
* 回復此版本

重要規則：

* 上傳新版不可直接覆蓋正式版本
* 必須建立新版本
* 新版本完成檢查與測試後，才能切換為正式版本
* 原本版本需要保留，供查看或回復
* 正式發布前要顯示受影響客戶

# 十三、版型下架

下架版型時提供三種處理方式：

1. 停止新客戶選用，既有客戶繼續使用
2. 停止新客戶選用，並通知既有客戶更換
3. 全面停止使用

執行前顯示：

* 目前使用客戶數
* 受影響客戶清單
* 客戶使用的版型版本
* 預計停止時間
* 下架原因
* 是否通知客戶
* 建議替換版型

如果選擇全面停止使用，必須進行二次確認。

# 十七、客戶功能權限

客戶詳情頁的功能權限需要清楚顯示：

* 所屬產品
* 產品是否啟用
* 功能是否已釋出
* 功能總開關
* 客戶是否擁有該產品
* 客戶產品使用權是否有效
* 客戶特殊權限
* 使用額度
* 最終是否可使用
* 不可使用原因

客戶特殊權限：

* 使用系統預設
* 額外開啟
* 強制關閉

* 調整原因
* 生效時間
* 結束時間
* 調整人員
* 是否通知客戶

畫面需區分：

* 系統預設開放
* 客戶額外開放
* 客戶被強制關閉
* 產品維護中
* 功能維護中
* 客戶產品已到期
* 使用額度不足

最終權限判斷邏輯：

最終可以使用
＝產品已啟用
＋功能已釋出並啟用
＋客戶擁有該產品
＋客戶使用期限有效
＋客戶例外權限允許
＋使用額度足夠

若不可使用，必須顯示具體原因，不要只顯示「無權限」。
